# Azure 知识问答 + 能力边界技能

本技能是 Agent 的**通用兜底**，覆盖两种**非实时诊断**场景，回答基于 LLM 通用知识、不查询任何实时资源：

- **情形 A：知识问答** —— Azure 产品/概念解释、SKU 与限额、价格、区域可用性、方案对比、最佳实践，
  以及对用户粘贴的事件/日志/错误信息的**解释与翻译**。
- **情形 B：能力边界兜底** —— 用户要对**本 Agent 不支持的对象/维度**做实时诊断（VM 五类指标之外），
  礼貌说明能力边界并引导用户。

> 本 Agent 的**实时诊断**范围仅限单台 VM 的五类平台指标：CPU、内存、磁盘、网络、Resource Health。
> 本技能**不查询任何实时指标、不调用任何工具**。若用户要的是 VM 这五类的实时诊断，请改用对应诊断技能。

## 何时使用

**情形 A（知识问答）触发条件：**

- 询问 Azure 概念 / 产品对比 / SKU / 限额 / 价格 / 区域可用性 / 最佳实践 / 文档查询
- 粘贴一段 Resource Health 事件 / 错误码 / 状态描述 + 「这是什么意思 / 解释下 / 翻译下」
- 任何不针对具体 VM 取实时指标、而是求知识性解答的问题

示例：「Azure 数据库有哪几种」「D 系列和 E 系列 VM 有什么区别」「跨区可用性集和可用区有什么区别」、
粘贴 `We're sorry, your virtual machine isn't available...` + 「这是什么意思」。

**情形 B（能力边界兜底）触发条件：**

- 用户要诊断 **VM 以外的资源**：数据库、负载均衡器（LB）、应用网关（AppGW）、存储账户、网络（VNet/NSG）等
- 用户要诊断 **VM 内部、平台指标拿不到的维度**：具体进程、文件系统占用、应用日志、中间件状态等
- 任何超出 CPU / 内存 / 磁盘 / 网络 / Resource Health 五类的**实时诊断**请求

示例：「帮我查下 MySQL 数据库 xxx 的连接数」「看下负载均衡器的健康探测」「这台 VM 里哪个进程占内存高」。

## 概览（执行流程）

本技能为 **SKILL.md 驱动型**（无脚本、不调用任何工具）。
先调 `load_skill`(skill_name=azure-qa) 读取本指令，然后**判断属于情形 A 还是情形 B**，
按对应的「回答规则 / 输出格式」直接组织答案作为最终回复——不要调用 run_az、不要查任何实时资源。

1. 判断：是知识/解释类问题（情形 A），还是对不支持对象的实时诊断请求（情形 B）。
2. 情形 A → 用通识知识按「情形 A 回答规则」作答，开头加 `💡 知识问答模式` 标识行。
3. 情形 B → 按「情形 B 输出话术」原样输出边界说明，只替换占位符。
4. 招呼 / 无意义 / 空输入（如 `你好`、`在吗`、`1111`、纯标点或乱码、无任何明确诉求）→ 按「情形 A」的「招呼/无诉求引导语」原样输出**固定引导语**，**不要**回「与 Azure 无关，我无法回答」。

> 区分要点：用户**只是问知识/概念/含义** → 情形 A；用户**要对某个不支持对象取实时数据/诊断** → 情形 B。
> 「与 Azure 无关，我无法回答」**仅用于**用户提了一个明确的、确实与 Azure / 微软云无关的真实问题（如问天气、写诗、数学题）；对没有明确诉求的招呼或乱码，一律走固定引导语，不要拒答。

## 情形 A：知识问答

### 回答规则（务必遵守）

1. 只回答与 Azure / 微软云相关的问题。**仅当**用户提出明确的、确实与 Azure 无关的真实问题（如天气、写诗、数学题）时，才回「该问题与 Azure 无关，我无法回答」；对没有明确诉求的招呼 / 无意义 / 空输入（`你好`、`在吗`、`1111`、乱码等），改用下方「招呼/无诉求引导语」，**不要**拒答。
2. 不要编造产品名、API 名、SKU 名、配额数字、价格。不确定的部分必须明确说「不确定，请以官方文档为准」。
3. 涉及具体 SKU / 限额 / 价格 / 区域可用性 → 必须附 https://learn.microsoft.com 链接，让客户核实。
4. 回答控制在 300 字以内，使用清晰的分点 / 列表格式（用 1) 2) - 等符号）。
5. 不要重复用户的问题，直接给答案。
6. 不要使用 Markdown 加粗 / 斜体（飞书纯文本展示）。

### 招呼/无诉求引导语（招呼、无意义、空输入时照此原样输出）

```
💡 知识问答模式（基于 LLM 通用知识，重要结论请以官方文档为准）
请说明您想查询的 Azure 内容。
如果您是要做 VM 实时诊断，请提供明确诉求，例如：
1) VM 名称 + CPU/内存/磁盘/网络/资源健康
2) 例如：`查看 vm-01 CPU`、`检查 vm-01 最近1小时内存`、`看 vm-01 资源健康事件`
```

### 输出格式

第一行固定为以下标识行，其后接你的回答正文：

```
💡 知识问答模式（基于 LLM 通用知识，重要结论请以官方文档为准）
<你的回答正文>
```

- 招呼 / 无意义 / 空输入 → 标识行后输出上面的「招呼/无诉求引导语」正文。
- 若问题是明确的、确实与 Azure 无关的真实问题 → 标识行后写「该问题与 Azure 无关，我无法回答」。
- 重要结论应提示用户以 Azure 官方文档为准。

## 情形 B：能力边界兜底

### 输出话术（照此输出，只替换占位符）

```
⚠️ 该请求不在我的实时诊断范围内（当前仅支持 VM 的 CPU / 内存 / 磁盘 / 网络 / 资源运行状态）。
您询问的【<用户问的指标/对象，无法确定时写“该指标”>】无法实时查询。
建议：1) 如需 Azure 通识问答，直接 @ 我提问即可（我会进入知识问答模式）；
     2) 如需对该资源做深度排查，请提单 Azure Support。
```

- `【】` 内填用户实际询问的对象（如「MySQL 连接数」「负载均衡器健康探测」「VM 内进程占用」）；无法确定时写「该指标」。
- 不要添加多余的前后缀、寒暄或臆测内容。

## 注意事项

- 本技能不读取任何实时资源数据、不调用任何工具。
- 情形 A 回答基于通用知识，重要结论应提示用户以 Azure 官方文档为准；尽量保留用户粘贴的原文语义，便于准确解释/翻译。
- 情形 B 不要臆测或编造不支持对象的诊断结果。
- 若用户其实是要某台 VM 的五类实时指标（CPU/内存/磁盘/网络/Resource Health），改用对应诊断技能，而非本技能。
